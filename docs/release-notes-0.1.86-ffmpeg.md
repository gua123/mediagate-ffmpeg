# 0.1.86-ffmpeg（versionCode 87）

修复「明明有网，App 却说没有网络」的问题。

## 现象

2026-11-03 真机截图：连接页两张卡都显示「当前没有网络，无法连接（未知网络）」，
但状态栏是 5G + VPN，同一张卡上的连通性测试却刚刚显示「正常（握手 834 ms）」；
点「设为当前连接」直接被拒——「连接『111 副本』当前没有可用地址：当前没有网络（未知网络）」。

## 根因

`AndroidNetworkMonitor` 之前用 `registerNetworkCallback(INTERNET)` 跟踪**所有**带上网能力的网络，
并在 `onLost` 里直接把全局现场写成「未知 + 离线」。任意一条被跟踪的网络消失（例如刚切走的 Wi-Fi、
断开的 VPN、来电期间的网络重注册）都会触发它；而新的默认网络早已就绪、不会再发一次 `onAvailable`，
于是现场永远停在「离线」，选路直接判 OFFLINE，连接被拦死。

## 修法

- 改用 `registerDefaultNetworkCallback`，只跟踪**默认网络**；
- 每个回调都**重新读 `manager.activeNetwork` 的现场**，不再相信回调参数；
- 现场没变不推新值（避免「刷新→重算→再刷新」循环）；
- `online` 不再强制要求 VALIDATED——VPN / 没外网的局域网常拿不到该标记，误判离线会拦死本来能连的 NAS；
  真正的可用性交给协议探测；
- 回前台（MainActivity.onResume）与「设为当前连接」前各主动刷新一次，作为丢事件时的自愈。

## 升级

应用内更新（0.1.84 起）或直接安装本 Release 的 APK。另外本版同样包含 0.1.85 的「公网预热收敛」。

装好后验证：
1. 状态栏有 5G/VPN 时，连接页不再显示「当前没有网络（未知网络）」；
2. 点「设为当前连接」不再被拦，浏览/播放能正常开始；
3. 公网进目录与播放是否比之前明显恢复。
