# 0.1.87-ffmpeg（versionCode 88）

修「内网播放也卡、像慢放」：自研 FFmpeg 引擎的**送屏路径太重**，不是网络问题。

## 定位

2026-11-03 用户反馈：内网播放同样很卡，感觉和播放引擎有关。查引擎代码发现每帧送屏要做三件重活：

1. `sws_scale` 把解码帧转成 RGBA（bilinear）；
2. `blitRgba` 里**逐像素**做 RGBA→BGRA 通道交换（1080p 每帧约 200 万次带分支的读改写）；
3. 每帧先把**整屏**清成黑色（又一个 200 万次的循环）。

软件解码 + 两次百万级逐像素循环叠在一起，中低端机/高分辨率视频很容易压不到 30fps；而 Media3 走硬件解码 + Surface 直出，所以同样的内网它不卡。

## 改动

- 缩放器直接输出 **BGRA**（与 Surface 内存字节序一致），送屏改成**按行 memcpy**，去掉逐像素交换；
- 清屏从逐像素循环改成 `std::fill_n`（编译器可向量化）；
- 缩放算法从 `SWS_BILINEAR` 改为 `SWS_FAST_BILINEAR`（画质差别肉眼基本看不出，省 CPU）。

这是纯引擎侧优化，网络/缓存策略不变；本版同时包含 0.1.86 的网络现场误判修复与 0.1.85 的公网预热收敛。

## 验证

装好后播同一批内网/公网视频，重点看：

1. 是否还像慢放/卡顿；
2. 设置 → 诊断与日志里的最近播放指标：**丢帧**是否还快速上涨、**音画偏差**多大；
3. 如果仍然卡，请把诊断卡的「画面 编码 宽x高」那行一起发我——**如果是 4K/HEVC，软件解码本身就跑不动，下一步要上 MediaCodec 硬件解码**。
