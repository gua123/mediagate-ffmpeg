# 0.1.85-ffmpeg（versionCode 86）

公网「一直转圈」的收敛版：这次不改播放引擎，改的是**App 自己在后台抢占带宽和 SFTP 通道**的行为。

## 定位

2026-11-03 公网真机：连接测试正常（独立探针会话，DNS 0ms / TCP 1ms / 握手 1103ms），
但打开未缓存视频一直转圈、下载只有 ~70 KB/s；退回目录再点上一级也还在转。

原因是「打开文件夹自动预热」：每进一个目录，会对前 12 个视频各抓「头 2 段 + 尾 1 段」＝12 MB，
2 个文件并发；这些预取任务挂在应用级作用域（退出播放也不会停），而 SFTP 通道池只有 4 条——
公网慢链路下，预热会把带宽和通道一直占着，播放和列目录只能排队。

## 改动（公网自动收敛，局域网保持原策略）

- 公网**不再做「打开文件夹自动预热」**（只预热你真正打开的那个文件）；
- 公网预读从 4 段压到 **1 段**；
- 打开文件时的预取只留「起播点 + 尾段（moov）」，并且**顺序发**，不再一次并发占满通道；
- 滑窗预取公网 **1 段 / 1 并发**；
- 公网**不预热下一集**；
- 拖拽落点预取公网 **1 并发**。

以上策略收在纯函数 NetworkPrefetchPolicy（6 条单测钉住）；局域网行为不变。

## 升级

应用内更新，或直接安装本 Release 的 APK。装好后请重点验证：
1. 公网进目录是否秒开（不再长时间转圈）；
2. 打开未缓存视频的首帧等待是否明显变短；
3. 如果仍然转，把「设置 → 诊断与日志」里的网络统计/面包屑发我。
